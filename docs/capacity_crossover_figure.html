Reading it. Each on-chip line rises with library size and eventually crosses the device limit, after which the design cannot be built. Which K that happens at is set entirely by precision — 222 for int32, 890 for int8, 4,449 for binary, a 32× span for the same application and the same source code. The streaming design's on-chip cost does not depend on library size at all.

Two points are tool-confirmed. At K = 128 (2,320 blocks predicted) Vivado synthesised and placed the design at 58.85% block RAM. At K = 256 (4,640 predicted) Vivado reported 115.40% and refused placement with a resource over-utilisation DRC error. The model predicted both within 1.4 percentage points.

The cost. Streaming runs 1.33× slower than on-chip wherever both exist — a 512-bit port at 300 MHz demands 19.2 GB/s while one U280 HBM2 pseudo-channel delivers 14.4. That is the price of removing the ceiling: unbounded library capacity for 33% latency. Prior work does not get to make that trade, because on-chip is its only option.
